### 2.5 支付渠道适配器（扩展点）

```

├── channel()                渠道标识，如 MOCK / WECHAT

├── parseCallback(body, hdr) 解析渠道报文 → CallbackResult(orderNo, transactionNo, amount, success, message)
```

## 4. 模块间调用关系（关键流程）

### 4.1 认证与鉴权

```
登录页 → api/auth.ts#login
      → POST /api/v1/auth/login
      → AuthController → AuthServiceImpl（BCrypt + 状态校验）
      → JwtUtil 签发 access(2h)/refresh(7d) → TokenStore 记录 refresh jti
      → 返回 LoginVO{accessToken,refreshToken,expiresIn,user}
      → stores/user.ts 落 token → guard 按 role 跳 homePath

后续请求 → request.ts 注入 Authorization
        → TraceIdFilter → JwtAuthenticationFilter（解析 + 黑名单校验）
        → @PreAuthorize("hasAnyRole('FINANCE','ADMIN')")
        → Service 内 SecurityUtils 做数据权限（学生仅本人）
```

### 4.2 下单 → 支付 → 回调（README 10.5 幂等要求）

```
① POST /v1/orders            Header: Idempotency-Key
   OrderServiceImpl.create:
     幂等键已存在 → 直接返回已有订单（同 orderNo）
     校验 item.status=PUBLISHED、now ∈ [startTime,endTime]、学生命中 targetScope、未缴清
     复用该学生该项目的未过期 PENDING 订单，否则新建（orderNo + expire_at=now+30min）
     insert 命中 uk_idempotency → 视为并发重复，查回已有订单返回

② POST /v1/orders/{orderNo}/pay
   UPDATE payment_order SET status='PAYING' WHERE order_no=? AND status='PENDING'（乐观更新）
   adapter.createPayment(order) → PayVO{payUrl,payParams,expireAt}

③ POST /v1/pay/callback/{channel}   （匿名放行）
   adapter.parseCallback → 校验渠道一致、金额一致
   UPDATE ... SET status='PAID',transaction_no=?,paid_at=NOW()
     WHERE order_no=? AND status='PAYING'
   影响行数 0 → 查最新状态：已支付=重复回调，静默成功；已关闭/已退款=告警日志，不改状态
   渠道流水号唯一冲突 → 60003 重复支付

④ OrderCloseJob（每 5 分钟）兜底关闭超时 PENDING 订单
```

### 4.3 退款

```
财务 → POST /v1/orders/{orderNo}/refund {amount, reason}
     → 校验 status ∈ {PAID, PARTIAL_REFUND}、amount ≤ 可退金额（订单金额 - 已退成功金额）
     → adapter.refund(...) → 写 refund_record
     → 累计退款额 = 订单金额 ? REFUNDED : PARTIAL_REFUND
     → 超额 → 60005；状态不允许 → 60002
```

### 4.4 对账

```
财务上传账单 CSV（channel + billDate + file）
  → create：渠道/日期唯一校验（重复 → 60009）、文件落 ${UPLOAD_DIR}/recon/{batchNo}.csv、批次 PENDING
  → match：解析 CSV（首行含「订单号」或 order 视为表头跳过；列序：订单号,渠道流水号,金额）
      本地侧取该渠道该日已支付订单
      逐笔匹配：渠道流水号优先 → 订单号兜底
        MATCH（金额一致，自动 HANDLED）/ AMOUNT_DIFF / CHANNEL_ONLY
      本地有、账单无 → LOCAL_ONLY
      重算批次统计；无差异则直接 FINISHED
  → details：差异明细分页（可按 diffType 过滤）
  → handle：逐条核销（HANDLED/IGNORED + 备注），全部处理完 → FINISHED
```

### 4.5 统计与导出

```
GET /v1/stats/overview  → receivable / received / outstanding / payRate / 订单数 / 缴费人数
GET /v1/stats/by-item   → 按项目聚合（应收/实收/笔数）
GET /v1/stats/by-college→ 按学院聚合（人数/应收/实收）
GET /v1/stats/trend     → 按 day/month 聚合（DATE_FORMAT 分组）
GET /v1/stats/export    → EasyExcel 流式写出 xlsx（Content-Disposition 中文文件名）
```

> **缴费进度口径（实现补充，README 未定义）**
> `paidAmount`、`remainAmount` 与下单金额统一按「**净已缴 = SUM(paid_amount) − SUM(成功退款金额)**」计算。退款不会回写 `payment_order.paid_amount`，若只按 `SUM(paid_amount)` 判断，部分退款的项目会被误判为已缴清并拒绝补缴。
> `payStatus`：净已缴 `<= 0` → `UNPAID`，`< 项目金额` → `PARTIAL`，`>= 项目金额` → `PAID`。
> `/available` 支持 `payFilter=ALL|UNPAID|PAID`，学生首页「待缴项目」用 `UNPAID`，因此已缴清的项目不会再出现在待缴列表里。

> **按需引入的两个坑（已修）**
> 1. `ElMessageBox` / `ElMessage` / `ElNotification` / `v-loading` 没有模板标签，`unplugin-vue-components` 扫描不到，**必须在 `main.ts` 显式 `import 'element-plus/es/components/xxx/style/css'`**。漏了会让确认框失去 `.el-message-box` 样式——跑到左上角、宽度塌成一条、按钮竖排。

## 9. 存疑 / 需产品确认的部分

| # | 事项 | 当前实现 | 需要确认 |
|---|---|---|---|
| 9.1 | **已关闭/已退款订单收到支付成功回调** | 不改状态、记 `WARN` 日志、**返回成功**（避免渠道无限重试），差额靠对账 `CHANNEL_ONLY` 发现 | 是否要求返回失败让渠道重试？或要求自动「复活」订单？ |
| 9.2 | **幂等键作用域** | `uk_idempotency` **全局唯一**（未按用户/项目隔离） | 若学生端每次下单都生成新 UUID，全局唯一无影响；若允许客户端固定键，建议改为 `(student_id, idempotency_key)` 联合唯一 |
| 9.3 | **对账 `diffCount` 口径** | 含 `CHANNEL_ONLY` + `AMOUNT_DIFF` + `LOCAL_ONLY`；`totalCount` 只统计**账单行数** | 财务口径是否要把 `LOCAL_ONLY`（本地有账单无）单列？批次列表是否显示「本地笔数」？ |
| 9.4 | **分次缴费** | `allow_partial=1` 时：未传 `amount` 默认收「剩余应缴」；不限制最少分几次 | 是否需要「分几期、每期金额」的缴费计划？现在只支持「想交多少交多少」 |
| 9.5 | **统计口径** | 应收 = 项目金额 × 命中适用范围的学生数；实收 = 已支付金额 − 已退金额；按**支付时间**聚合趋势 | 是否按学期/学年出账？退费是否冲减原期趋势？ |
| 9.6 | **token 存储位置** | 前端存 `sessionStorage`（README FAQ Q6 提到 `localStorage`） | `sessionStorage` 更安全（关标签页即失效）但多标签不共享登录态；是否改用 `localStorage` + 过期校验？ |
| 9.7 | **凭证形式** | 服务端返回**内联 HTML**（可打印/另存 PDF），非 PDF 文件 | 是否需要直接下发 PDF（引入 iText/OpenPDF）？ |
| 9.8 | **通知可见性** | 财务/管理员可见全部（含草稿）；学生仅见已发布且 `targetRole` 命中、未过期 | 是否允许财务给「指定学生」定向发通知？现仅支持按角色 + 可选 `itemId` |
| 9.9 | **操作日志范围** | 只对显式标注 `@LogOperation` 的写操作记录，未覆盖查询 | 是否需要记录敏感查询（如导出）以备审计？ |
| 9.10 | **导出数据量** | EasyExcel 流式写出，未做上限保护 | 十万级以上是否需要异步任务 + 下载中心？ |
